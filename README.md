# Food Delivery System

A console-based **Food Delivery System** developed using Java, Maven, Lombok, and JUnit 5.

The application follows a layered architecture:

**UI → Controller → Service → Repository → CSV**

## Features

* Add a new customer
* Find a customer by Customer ID
* View all customers
* Place a food order
* Validate customer existence before placing an order
* Prevent duplicate Customer IDs
* Prevent duplicate Order IDs
* Validate that order quantity is greater than 0
* Calculate total order amount
* View all orders
* Find an order by Order ID
* View orders for a specific customer
* Persist customer and order data using CSV files
* Load existing CSV data when the application starts

## Technologies Used

* **Java 17+**

```text
                   ▼       ▼
               ArrayList   CSV
```

### UI

The UI handles:

* Menu display
* User input using `Scanner`
* Displaying application output

The UI does not directly access the Repository.

### Controller

The Controller acts as a bridge between the UI and Service layer.

### Service

The Service contains the business logic, including:

* Duplicate customer validation
* Customer existence validation
* Duplicate order ID validation
* Quantity validation
* Total amount calculation

### Repository

The Repository handles:

* Customer and Order lists
* CSV loading
* CSV saving
* Searching records
* Adding records

The Repository is the only layer that directly handles CSV files.

## Design Patterns

### Singleton

The following classes use the Singleton pattern:

* `FoodDeliveryController`
* `FoodDeliveryService`
* `FoodDeliveryRepository`

This ensures that only one instance of each component is used.

### Factory

`FoodDeliveryFactory` provides the Singleton instances of:

* Controller
* Service
* Repository

## Data Persistence

Customer data is stored in:

```text
src/main/resources/customers.csv
```

Order data is stored in:

```text
src/main/resources/orders.csv
```

Existing records are loaded when the application starts.

New customers and orders are saved to the corresponding CSV files.

## Testing

Repository functionality is tested using **JUnit 5**.

The tests use temporary CSV files so that test execution does not modify the application's production CSV files.

To run the tests:

```bash
mvn test
```
